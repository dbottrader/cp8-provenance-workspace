## 1. Major methodological correction discovered

The normalized file `FULL_CHATGPT_EXTRACTION_2026-05-21.txt` contains 1,014 conversations and labels each conversation with a **thread creation date**. That date cannot automatically be used as the timestamp of every message inside the thread.

A programmatic audit found **27 of 1,014 threads (2.66%)** contain explicit 2025 dates later than the thread-header date, proving that some old threads were reopened and continued later.

Examples:

- `DMT overview` — thread header: **2025-08-12**; later content inside the same thread explicitly carries **2025-10-08 / 2025-10-09**.
- `Greeting conversation` — thread header: **2025-09-06**; later content explicitly carries **2025-10-07 / 2025-10-08**.
- `Export Codex Master Index Reminder` — thread header: **2025-09-16**; later content explicitly contains an **October 2** daily drop and other later activity.

### Consequence

Any chronology based only on “earliest conversation containing a term” is unsafe.

From this point forward, timestamps are classified:

- **T0 — message timestamp:** original per-message timestamp from raw ChatGPT JSON. Highest value; still needed for exhaustive proof.
- **T1 — embedded event date:** explicit date key/timecode inside the actual passage.
- **T2 — thread-start event:** target event occurs at or near the beginning of a newly created thread and no later-date marker precedes it.
- **T3 — thread-header only:** term occurs somewhere inside a reused thread. Not acceptable as an origin date.
- **T4 — Drive file creation:** establishes file existence in Drive, not original conversational creation.

This correction supersedes any v1.1 inference that used a reused thread's creation date as an event date.
